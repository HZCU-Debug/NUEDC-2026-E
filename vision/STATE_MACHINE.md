# 树莓派—ESP32视觉状态机

最后核对：2026-08-04

## 自动任务流程

```text
WAIT_CMD / READY FOR NEXT ESP32 MODE
  ↓ 收到可靠 TYPE=0x03, PAYLOAD=0..4
CALIBRATING（Mode0）或 DETECTING（Mode1..4）
  ↓ 连续两帧的数量与几何均稳定
SOLVING
  ├─ 失败且未到90s：记录诊断，等待0.75s，重新采集两张新稳定帧
  ├─ 每次失败：保存并跨帧比较最佳近似拼图候选
  ├─ 到90s仍无正常解：发送累计最佳近似拼图
  ├─ 取消：收到0xFF，清空当前任务，不发送动作
  └─ 成功：生成完整且已通过安全检查的动作计划
SENDING_COUNT
  ↓ 数量包ACK
SENDING_PIECES
  ↓ 每个动作包分别等待ACK
WAITING FOR MODE LINE TO BECOME QUIET
  ↓ 连续安静1秒
READY FOR NEXT ESP32 MODE
```

求解失败不会立即结束当前 ESP32 任务，也不会发送伪造坐标。程序反复采集新稳定帧，
但从收到本次Mode命令开始最多等待90秒。每次失败都保留求解器已经生成的最佳近似
拼图，跨帧依次按“已匹配碎片数更多、已匹配接缝数更多、求解评分更好”比较。到时仍无
正常解，就发送90秒内累计最佳候选；例如三块关系正确而第四块错误的候选优先于四块
无关系的整齐摆放。该计划标记 `best_effort=true`、`puzzle_solved=false`，并继续保证
坐标合法、零重叠和8 mm间隔。只有没有安全候选时才用紧凑搬运末级兜底。稳定判断还会
比较碎片数、顶点数、质心、顶点和边长。

Mode1保存模板RMS最小候选；Mode2/3保存匹配碎片数、接缝数和几何评分最优候选；
Mode4保存接缝、双轴花纹和综合评分最优的被拒牌面候选。四种模式都启用90秒截止。
`--manual` 调试模式不自动触发该截止。若标定或碎片检测失败到无法产生可信抓取坐标，
则既没有求解候选也不能安全执行紧凑搬运，禁止为了“必须输出”而伪造坐标。

## Mode命令和忙碌行为

ESP32向树莓派发送：

```text
TYPE    = 0x03
PAYLOAD = uint8 mode
```

合法 payload：

- `0`：两段式固定标定；
- `1..4`：对应四种求解模式；
- `255/0xFF`：取消当前检测、求解、自动重试或发送。

当前任务活动、结果正在发送或输入尚未重新 armed 时，新 Mode 会被忽略，不会打断
机械臂。任务完成后必须先看到：

```text
WAITING FOR MODE LINE TO BECOME QUIET
READY FOR NEXT ESP32 MODE
```

`READY` 表示Pi已经重新允许接收新命令；如果ESP32按钮没有产生新的可靠帧、仍在重复
旧序号，或者ESP32自身仍忙，Pi不会凭终端状态主动启动任务。

## Mode0固定标定

1. 第一次可靠发送 Mode0，进入 `CALIBRATING`；
2. 放置 `105×297 mm` 湖蓝色半张A4；
3. 至少连续两帧角点稳定；
4. 第二次可靠发送 Mode0，保存并热加载 `rpi_camera_calibration.json`；
5. 移走蓝卡，等待 Mode 线安静后发送 Mode1～4。

第二次Mode0到达时若角点不稳定，程序不会保存，也不会退出标定。没有正式标定文件时，
Mode1～4会被拒绝，不会输出未经标定的坐标。

## 四种求解路径

### Mode1

检测必须恰好为4块。所有碎片与固定模板尝试最佳分配、旋转和平移；任何一块的最佳
轮廓 RMS 超过 `8 mm` 时安全拒绝。匹配通过后从无间隙模板开始，统一应用真实接缝边
法向 `8 mm` 间隙，再放置到距中线 `10 mm` 的目标区。

### Mode2/3

Mode2在四块碎片均通过高置信度矩形检查时，先使用全矩形专用布局，枚举横/竖切分、
2×2和T形组合；它只要求得到任意合法矩形，专用布局失败后回退通用搜索。两者其余
情况共用角驱动、完整边和分段边几何搜索，以及同一最终矩形校验。Mode3使用更宽的
搜索调度和自适应反向绿色轮廓分割。矩形尺寸和外边合法性在加间隙前验证；通过后才
把相邻接缝边分开 `8 mm`，最后检查零重叠和工作区。

Mode3自动调度前两次新帧使用 `beam=40→400`；证据不足时40路线自动跳过。连续失败
两次后追加 `beam=1600`。角驱动只是快通道，不适合T形/长边内部接缝时会回退常规边。

### Mode4

只接受2～4块近似直角矩形牌片。候选先做矩形规范化和槽位分配，再验证右上/左下角标、
长短双轴和180°证据。旧拼缝形态学已完全停用，结果记录：

```text
seam_diagnostics_computed=false
```

歧义或像素证据不足时安全拒绝。

## 结果消息

先发送碎片数量：

```text
TYPE    = 0x01
PAYLOAD = uint8 count
```

随后按机械执行顺序逐块发送：

```text
TYPE    = 0x02
PAYLOAD = >Bhhhhh
```

| 字段 | 类型 | 单位 |
|---|---|---|
| `piece_id` | `uint8` | 碎片编号 |
| `source_x/source_y` | `int16` | mm |
| `target_x/target_y` | `int16` | mm |
| `rotation` | `int16` | `0.01°`，顺时针为正 |

所有动作在发送前已完成坐标范围、目标半区、零重叠、接缝间隙和模式专用安全检查。

## 链路层

串口默认 `/dev/serial0`、`115200 8N1`：

```text
帧 = COBS(原始包) + 00
可靠消息 = TYPE|80  SEQ  PAYLOAD  CRC
ACK      = 00       SEQ           CRC
```

CRC-8多项式为 `0x07`，初始值和最终异或值均为 `0x00`。未收到ACK时发送端重发同一
序号帧；重复帧不能被当成新的Mode任务。
