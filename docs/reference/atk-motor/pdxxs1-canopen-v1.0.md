注意事项(必读)
在使用 PDxxS1 步进电机 FOC 闭环驱动器 的 CANopen 通信功能前，请务必阅读并
遵守以下说明：
1. 硬件版本要求
PDxxS1 系列驱动器提供 TTL、RS485 和 CAN 多种通信版本。其中 CANopen 协
议仅在 CAN 版本硬件上支持。
2. CAN 总线连接要求
使用 CANopen 通信时，需正确连接 CANH 与 CANL 总线信号，并确保 CAN 总
线两端各接入 120Ω 终端电阻，以保证总线通信稳定。
3. CANopen协议选择
可通过以下两种方式将驱动器切换为 CANopen 协议：
⚫ 面板设置：长按右键进入菜单，选择“通信协议 → CANopen”，完成切换；
⚫ 指令设置：通过发送功能码 0x69 的命令，将协议设置为 CANopen。
具体指令格式及操作方法，请参考《PDxxS1 步进电机闭环驱动器用户手册》第
4.3.29 小节。
4. Node ID 唯一性
CANopen 网络中，每个从节点必须配置 唯一的 Node ID。若存在重复 Node ID，
可能导致总线通信冲突或节点无法正常工作。Node ID 可通过以下两种方式设置：
⚫ 面板设置：长按右键进入菜单，选择 “ID 地址”，按需选择所需的 Node ID 地址；
⚫ 指令设置：通过发送厂商自定义索引码 0x2030 的命令，设置 Node ID 地址，地址
范围为 1~127。具体指令格式及操作方法，请参考第10.3 小节。
5. 波特率一致性
CAN 总线上所有设备必须配置 相同的通信波特率，否则节点之间将无法建立正
常通信。默认波特率：500 Kbps
6. 主站设备要求
使用 CANopen 控制 PDxxS1 时，需要配合 支持 CANopen 协议的 CAN 主站设
备，如 PLC、上位机软件或嵌入式控制器等。
7. 协议支持说明
PDxxS1 CAN 版本驱动器支持 CANopen 协议通信控制，并提供对应的 对象字典
（Object Dictionary）和控制指令，用户可通过 CANopen 主站对驱动器进行参数
配置与运动控制。

1，CANopen 简介
CANopen 是一种基于 CAN 总线（Controller Area Network） 的工业现场总线高层通
信协议，由 CAN in Automation（CiA）国际组织制定和维护。该协议具有 实时性高、通信
可靠、网络结构简单、设备兼容性强 等特点，广泛应用于 工业运动控制、伺服与步进驱动、
机器人系统、自动化产线以及智能装备等领域。
PDxxS1 步进电机驱动器支持标准 CANopen 通信协议，并具备以下核心功能：
• 兼容 CiA 301 标准：支持 CANopen 基本通信协议规范
• 兼容 CiA 402 设备规范：支持标准运动控制设备模型
• PDO 通信机制：支持实时过程数据（Process Data Object）传输
• SDO 服务机制：支持参数配置与对象字典读写
• 网络管理功能：支持 NMT 网络管理、Heartbeat 心跳监测以及 EMCY 故障报文
• 运动控制模式：支持 位置模式、速度模式和力矩模式 等多种控制方式
通过 CANopen 协议，用户可以实现 设备参数配置、状态监测以及多轴运动控制，并
能够方便地与 PLC、上位机或嵌入式控制系统集成。

2，CANopen 网络结构
CANopen 网络通常采用 主从式（Master–Slave）架构，由主站和多个从站组成：
• Master（主站）：如 PLC、运动控制器或上位机等设备，负责网络管理、控制指令
下发、节点状态管理以及数据采集。
• Slave（从站）：如 PDxxS1 步进驱动器，接收主站发送的控制指令，执行运动控制，
并向主站反馈运行状态和数据。

每个从站必须配置 唯一的 Node ID，取值范围为 1～127，不能重复。

计算规则
3.1 CAN ID
  PDxxS1 步进驱动器采用 CANopen 标准的 11bit 标准 ID（CAN 2.0A），用于标识不
同类型的 CANopen 报文，确保主从站之间的通信准确无误。11bit CAN ID 的核心构成的
是“功能码 + 节点ID（NodeID）”，其中功能码用于区分报文类型（如 SDO、PDO、NMT），
节点ID用于区分同一网络中的不同从站设备。
计算方式：
CAN ID = 功能码（高4位） + NodeID（低7位）
说明：11bit CAN ID 的取值范围为 0x000~0x7FF，其中高4位（bit10~bit7）为功能码，

数据格式：

|     | CAN_ID  | DLC  |        | 数据       |
| --- | ------- | ---- | ------ | -------- |
|     | 000H    | 02H  | Byte0  | Byte1    |
1，CAN ID：固定为 0x000（广播地址），所有从站均会接收该报文；
2，数据长度：固定为 2 字节；

表8.1.1 SYNC 报文格式
在 CANopen 系统中，SYNC 报文用于为网络中的节点提供统一的同步触发信号。主
站周期性发送 SYNC 报文，从站根据 PDO 的 Transmission Type（传输类型） 设置，在
指定的 SYNC 周期触发 PDO 的发送或执行。
在大多数应用中，SYNC 报文 不包含数据（DLC = 0），仅作为同步触发信号使用。从
站每接收到一次 SYNC 报文，其内部同步计数器会递增，并根据 Transmission Type 判断
是否触发 PDO。例如，当 Transmission Type 设置为 5 时，从站需要接收到 5 次 SYNC 报
文 才会触发一次对应的 PDO 操作。
CANopen 规范也允许 SYNC 报文 携带 1 字节数据（DLC = 1），该字节表示 SYNC
计数值（1～240）。从站在接收到 SYNC 后，会将该计数值与 Transmission Type 进行比较，
当两者相等时触发对应的 PDO 操作。

1. 优先使用 CiA402 标准对象
对于电机的位置控制、速度控制和力矩控制，推荐优先使用 CiA 402 标准对象字典中
的控制对象，例如：
⚫ 0x607A 目标位置
⚫ 0x60FF 目标速度
⚫ 0x6071 目标力矩
采用 CiA 402 标准对象具有以下优势：
• 标准兼容性高
可与绝大多数符合 CANopen 标准的主站控制器（PLC、运动控制卡等）直接兼容。
• 支持 PDO 高速通信
标准对象通常已预映射至 PDO，可实现实时、高速的运动控制数据交换。
因此，在涉及实时运动控制的场景中，推荐优先使用 CiA 402 标准对象进行控制。
